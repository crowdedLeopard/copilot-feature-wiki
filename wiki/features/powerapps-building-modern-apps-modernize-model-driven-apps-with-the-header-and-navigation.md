## What's changing

Model-driven apps in Power Apps gain a redesigned app shell: a modern app header, a streamlined sitemap and a reworked form layout. Microsoft Learn calls this wave 2 of the modernisation of model-driven apps, which builds on the New Look (wave 1).

The changes users will notice, as the roadmap item and Learn describe them: the command bar is the only element fixed at the top of a form, while the summary area and form header scroll away and a condensed sticky header attaches below the command bar; the form header adapts better to window sizes; spacing and margins are tighter; and injected system commands such as **Show As** and **Show Chart** now appear in third position, after **New** and **Delete**. Learn also notes that on forms the command bar is no longer embedded in the form header as it was during preview, and that the record set navigator is back in the command bar.

The roadmap item describes a **Header and navigation refresh** app setting with three values: **Auto (default)**, where the new experience is off except for apps created using Plans; **Yes**; and **No**. The Learn page describes the opt-in differently: in the app designer, select **Settings**, then **Features**, then enable **Header and navigation refresh**. Learn adds that the refresh applies automatically to apps generated by the Plan designer, and that you must have the New Look enabled to see it.

The roadmap item is in the status Rolling out, with a target date of September CY2026 and a preview date of May CY2025, for the Worldwide (Standard Multi-Tenant) cloud on the Web platform. The record lists release phases General Availability and Preview, the Weekly release channel and version 2609.1. Learn states that general availability begins with build 2609.1 and that availability might vary by region as the build rolls out.

## Why it matters

For service owners this is a visible change to the screens that business users work in all day, with no new data access or security behaviour described in the feature documentation. Because existing apps are opt-in, nothing changes for them until a maker enables the setting, so the decision is when to switch each app and how to prepare its users. Apps generated by the Plan designer are the exception: Learn says the refresh applies to them automatically, so users of new Plan-built apps will see it from the start.

Expect questions rather than incidents: scrolling headers, a different sitemap and moved commands generate support calls and training notes. Learn's known limitations for the modern look (classic theme customisations are no longer honoured, only SVG navigation icons are supported, dark mode and theme switching are not supported) are worth checking against your apps before switching.

## Risk assessment

**Data exposure**

- No change documented: the refresh alters layout and navigation. Microsoft Learn describes no new data access or data movement for it.

**Security & identity**

- No change documented: neither the roadmap item nor the Learn page describes new permissions, roles or sign-in behaviour for this refresh.

**Autonomy & actions**

- No autonomous behaviour is described. The refresh is a user interface change; the only automatic part Learn states is that apps generated by the Plan designer get it.

**Change & support**

- The command ordering changes: **Show As** and **Show Chart** move to third position, after **New** and **Delete**. Update any training material or screenshots that show the old command order, and tell power users before a switch.
- The form header and summary area scroll off the page, with a condensed sticky header below the command bar. Users who relied on a fixed header on long forms will notice this.
- The sitemap in Plan designer apps is a flat list: Learn says the designer turns off **Home**, **Recent**, **Pinned** and sitemap groups by default for those apps, so their navigation will look different from your existing apps.
- Learn lists limitations of the modern look that apply once the refresh is on: classic theme customisations are no longer honoured (app header colour can be overridden), custom navigation icons must be SVG or a default icon appears, and switching themes or dark mode is not supported.
- Learn says the header and navigation refresh cannot be turned on without the New Look.

## Cost and licensing

Model-driven app use requires a licence providing Power Apps premium use rights: the [Power Apps licensing FAQs](https://learn.microsoft.com/power-platform/admin/powerapps-licensing-faq) say model-driven apps use Dataverse and are premium apps by default, and that every user who runs one needs a licence that provides those rights. Microsoft has not published an additional licence requirement or a meter specific to the header and navigation refresh. The roadmap record gives the feature scope as users, enabled by admins or makers, and the Learn page for the feature, [Modern, refreshed look for model-driven apps](https://learn.microsoft.com/power-apps/user/modern-fluent-design), lists no licence or charge for it. An additional licence or meter for the refresh is therefore Not yet published.

The cost the sources do show is indirect: maker time to test each app with the refresh enabled, user communication and updated training material.

## Scope

**Who and what:** model-driven apps in Power Apps, per the roadmap record's "Applies to" field. The roadmap lists the Worldwide (Standard Multi-Tenant) cloud and the Web platform, so no US Government cloud is listed on the record.

**Rollout:** the record gives the Weekly release channel and version 2609.1. Learn states that general availability begins with build 2609.1 and that availability might vary by region as the build rolls out.

**Who turns it on:** per the roadmap record, it is enabled by admins or makers for end users. Learn says it is generally available and opt-in for existing apps, enabled through the app settings, and that it applies automatically to apps generated by the Plan designer.

**Prerequisite:** the New Look (wave 1). Learn says you must enable the New Look to see the header and navigation refresh.

**Related behaviour:** Learn states that the mail app and the mobile app support the modern, refreshed look, with their own enablement steps described on that page; the roadmap item lists the Web platform only.

## Governance guidance

### Before rollout

- Inventory the model-driven apps that matter most and ask makers to test each one with **Header and navigation refresh** enabled in a non-production environment.
- Check each app against the limitations Learn lists for the modern look: classic theme customisations, non-SVG navigation icons and any reliance on dark mode.
- Update training notes and screenshots for the new command order (**Show As** and **Show Chart** after **New** and **Delete**) and the scrolling form header.
- Tell makers that apps generated by the Plan designer get the refresh automatically, so their sitemaps will look different from existing apps.

### At rollout

- Have makers enable the setting one app at a time: in Power Apps, select **Solutions**, choose the solution, select **Apps**, select the app, select **Edit**, then in the app designer select **Settings** > **Features**. Then save and publish the app, starting with a pilot group.
- Send users of each switched app a short note on the sticky condensed header and the moved commands.
- Decide whether to apply the roadmap's **Auto / Yes / No** values or the Learn page's **Features** toggle, and confirm which one your tenant shows before giving makers instructions.

### After rollout

- Collect support tickets and user feedback per app and decide which remaining apps to switch.
- Re-check the Learn page and the roadmap item for changes to the opt-in model, since the roadmap record gives a September CY2026 target and describes the experience as remaining opt-in as it transitions to general availability.
